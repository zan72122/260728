# 🌈 にじいろつみきタワー

4歳の女の子のための、3D「巨大積み木解体」ゲームです。
**約800〜2,500個**（端末性能に応じて自動調整）の虹色ブロックでできた
巨大なモチーフに **こわし装置** をとりつけて、**ぽんスイッチ**を押すと……
毎回すこし違うかたちで、ドカーン！がらがらっ！と崩れます。

文字が読めなくても遊べます。失敗はありません。
崩れなくても、崩れすぎても、ぜんぶ「たのしい結果」です。

---

## あそびかた

1. **そうちをえらぶ** … 画面下のパレットから好きな装置をタップ
2. **モチーフにつける** … ブロックをタップすると装置がカチッ（もう一度タップではずせる）
3. **ぽん！** … ピンクの大きなボタンで、つけた順番に装置が発動（0.75秒間隔の解体ショー）
4. **ながめる** … ドキドキ……シューッ……ドカーン！支えを失った塊がなだれ落ちる
5. **おそうじぽん** … 結果のあとは、タップした場所の塊ごとポン！と消せる（音階コンボつき）

### こわし装置（1ステージに 10〜16個 置ける）

| 装置 | おこること | とくい |
|------|-----------|--------|
| 💣 ばくだん | 導火線がシューッ→ドカーン！ 爆心は粉々の大穴、まわりは吹き飛ぶ | 広範囲・穴あけ |
| 💨 せんぷうき | 浮かんだ扇風機がビュオーッと3秒間送風。じわじわ押し崩す | 横からじわじわ |
| 🔨 ハンマー | 的マークの場所を大きなハンマーがゴツン！と一撃 | ねらった一点 |

穴が開いて支えを失った部分は、**塊ごと**なだれ落ちます。
「どこに何を置くと、どこまで崩れるか」を予想して遊びます。

### そうさ

- **タップ** … 装置をつける／はずす、ボタン、おそうじぽん
- **ドラッグ** … カメラをぐるっと回す ／ **ピンチ** … ズーム

### けっか

- 崩れた「高さの合計」が左のにじメーターにたまり、⭐1〜3個で評価（罰なし）
- **↺** … 同じモチーフでもう一回（予想の答え合わせ） ／ **▶** … つぎへ

## 動かしかた

ES Modules を使っているため、**HTTPで配信して開く**必要があります。

```bash
cd nijiiro-tsumiki-tower
npx serve .        # または python3 -m http.server 8000
```

GitHub Pages で公開すれば、iPad / iPhone の Safari から
「ホーム画面に追加」で全画面アプリのように遊べます（アイコン同梱）。

- 対応: iOS/iPadOS Safari(16+推奨)、Chrome、Edge。縦横両対応
- 外部通信なし・広告なし・課金なし。進行状況・品質設定は localStorage に保存
- 開発用: `?budget=500` のように URL でブロック数を固定できる

## 規模とマシン負荷の設計

ボトルネックは描画ではなく**物理演算**です。本作は2つの技術で
「iPhone/iPad のブラウザで数千ブロックが物理で崩れる」を成立させています。

1. **InstancedMesh 描画** … 全ブロックを1ドローコールで描画。
   描画側は 1万個でも余裕になる
2. **「触るまで凍結」物理** … 全ブロックは最初、物理コストほぼゼロの
   固定物。装置が当たった部分だけ動的ボディに変換し、
   - 支えを失った塊は **接地チェック**（地面との連結判定、0.35秒ごと）で
     検出して塊ごと落下させる
   - 落ち着いて眠ったブロックは**再凍結**（がれき化）して負荷から除外
   - 大量の塊が一斉に落ちる瞬間は、ソルバーを軽くし積極的に再凍結する
     **過負荷ガード**が働く

   結果、実際に動いているのは常に数百個だけ。おまけとして、
   ハートの張り出しやアーチなど「本来自立しない形」も作れる

3. **適応品質** … 崩壊中の実測FPSで次ステージのブロック予算を自動増減
   （800〜2,500）。速い端末は迫力へ、遅い端末は滑らかさへ

※ 5万個（1000倍）級はリアルタイム剛体物理では不可能なため対象外です。

## 検証（開発者向け）

```bash
node test/demolition.mjs
```

全モチーフ × 複数予算について、実シミュレーションで検証します。

1. **予算に収まる** … ブロック数が budget の 35〜130% に収まる
2. **接地している** … 生成直後に宙に浮いた孤立ブロックがほぼ無い
3. **ちゃんと崩れる** … 💣3個（実プレイの装置数の1/3以下）で高さの8%以上が
   崩れ、崩壊後に「宙に浮いたまま凍結」するブロックが1個も残らない
   （接地チェックの連鎖の正しさ）

ブラウザのコンソールでは `window.NIJI` から state / score / dynCount /
budget / fps がのぞけます（E2E テスト用フック）。

## 設計メモ

- **因果の見えやすさ**: 装置は「爆発・風・打撃」という現実で体感済みの
  因果をそのまま使用。発動は 0.75 秒間隔で1つずつ
- **爆発の物理**: 密着ブロックの山は接触と摩擦がインパルスを吸収するため、
  爆心近く（breakRadius）を粉砕して大穴を開け、強い上向き成分で
  宙に浮かせて摩擦から解放している（`demolition.js` の `bombParams`）
- **毎回ちがう結果**: 生成の色ゆらぎ+物理のカオス性+発動時の微小ランダム。
  同じシード（↺）でも少し変わる
- **罰なし設計**: スコアは「崩れた高さの割合」の加点のみ。0点でも祝福
- **チューニング**: 物理定数と爆弾は `js/demolition.js`、モチーフと配色は
  `js/voxels.js`、風・ハンマー・過負荷ガードは `js/main.js`
