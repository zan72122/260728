# 設計メモ

4さいのユーザーが iPad / iPhone で遊ぶことを前提にした、赤ちゃんのお世話ゲームです。
仕様の決定事項と、その理由・実装場所をまとめます。

## 決定した仕様

| 項目 | 決定 | 実装 |
|---|---|---|
| 表現形式 | 簡易3D（three.js） | `src/` 全体 |
| 絵柄 | 絵本寄り（やわらかい線・淡い色） | `scene/palette.js` のトゥーン素材＋`util/outline.js` の輪郭線 |
| 頭身 | 現実寄り（約4頭身） | `baby/baby.js`（頭 R=0.17 を基準に全身を組む） |
| 家の外観 | お城風ベビーハウス | `scene/room.js`（狭間・四隅の塔・とんがり屋根・旗） |
| 室内の色調 | 木目＋パステル | `scene/textures.js`（木目・石積みを canvas 生成） |
| 部屋構成 | 1部屋完結 | 4つのお世話の場所を1部屋の四隅に配置 |
| カメラ | 自由に動く＋状況により自動切替 | `camera/cameraRig.js` |
| 技術 | 単一HTML＋CDN（ビルド不要） | `index.html` の importmap |
| お世話 | おむつ・ミルク・ねんね・おふろ | `care/` |
| 進行 | 失敗なしの自由あそび（ほしシール） | `state/gameState.js`＋`scene/props.js` の StickerBoard |
| UI | アイコンのみ・完全無文字 | `ui/icons.js`, `ui/hud.js` |

## 4さい向けとして守ったこと

- **失敗の概念を作らない。** 制限時間・ゲームオーバー・減点はどこにもありません。欲求はたまるだけで、
  たまりきっても「ぐずり顔＋フキダシ」までで止め、泣きつづける状態は作りません。
- **操作は1種類だけ。** どのお世話も「指でドラッグする」だけで進みます。ボタンの二度押しや長押し、
  複雑なジェスチャーは使いません。
- **やり方は絵で見せる。** お世話がはじまると、指の動かし方をあらわす手のアニメ（`ui/style.css` の
  `hint-down` / `hint-side` / `hint-up`）がその場所に出ます。1回さわると消えます。
- **押しまちがえても平気。** もどるボタン（←）でいつでも中断でき、ペナルティはありません。
- **タップ領域を大きく。** ボタンは直径 84px（せまい画面で 68px）。画面のふちからは safe-area ぶん離します。

## 画面まわり

- **たて画面** … お世話ボタンは画面下に横一列。**よこ画面** … 右に縦一列。CSS のメディアクエリで切り替え。
- カメラは画面比に応じて引き（半径）を自動調整します（`CameraRig.setAspect`）。
  たて長の画面ほど大きく引いて、部屋全体が入るようにしています。
- iOS 対策：`viewport-fit=cover`、`touch-action: none`、`overscroll-behavior: none`、
  ダブルタップ拡大と2本指スクロールの抑止（`ui/input.js`）。

## カメラの考え方（自由＋自動切替）

1. ふだんは自由。1本指で周回、2本指でピンチズーム。角度と距離には上限・下限があり、
   床下や部屋の外には出られません。
2. お世話をはじめると `CameraRig.setPreset()` がその場所のプリセットへ寄せ、手動操作を一時的に止めます
   （お世話の指の動きとカメラ操作が競合しないため）。
3. お世話が終わると全景へ戻り、手動操作が復活します。
4. 何もしないまま 14 秒たつと、ゆっくり全景へ戻ります（迷子防止）。

手前にきた壁と塔は、カメラの向きに応じて自動で透けます（`Room.update` の fader）。
これにより、どの角度から見ても部屋の中が見えます。

## お世話の流れ（共通）

```
ボタン → 赤ちゃんを場所へ運ぶ（だっこ移動）→ enter()
      → 指のドラッグで進める → complete()
      → ほし＋きらきら＋わらい声 → もどる（ラグへ）
```

`care/base.js` が共通のかたちで、4つのアクションはこれを継承します。
コントローラー（`care/controller.js`）が移動・カメラ・ヒント・ごほうび・後片づけを担当します。

| お世話 | 操作 | 成立条件 |
|---|---|---|
| おむつ | 下方向にドラッグ | 下向きの移動量が 200px たまる |
| ミルク | びんを口まで運ぶ | 口との距離が 0.3 以内 → 自動で飲む（3.4秒） |
| ねんね | 左右になでる | 指の移動距離の合計が 1500px |
| おふろ | スポンジでこする | よごれ4か所をすべてこすり落とす |

いずれも「向きが合っていればいつか必ず終わる」設計で、速さや正確さは求めません。

## パフォーマンス

- 画像・音声・3Dモデルの外部ファイルは 0。すべてコード生成なので、初回読み込みは three.js 本体だけです。
- 影は方向光1つ（1024px）。壁は影を落とさず、受けるだけにしています。
- 狭間（壁の上のギザギザ）は `InstancedMesh` で1ドローにまとめています。
- パーティクルは 90 個のメッシュを使い回すプール方式（`scene/particles.js`）。
- `renderer.setPixelRatio(min(dpr, 2))` で Retina でも過剰に描かないようにしています。

## 画面の確認

`docs/screenshots/` に、たて・よこ 4パターンの実画面を置いています。

| ファイル | 想定 |
|---|---|
| `ipad-landscape.png` | 1180 x 820（iPad よこ） |
| `ipad-portrait.png` | 820 x 1180（iPad たて） |
| `iphone-landscape.png` | 844 x 390（iPhone よこ） |
| `iphone-portrait.png` | 390 x 844（iPhone たて） |

いずれもボタン・フキダシ・ヒントが重ならず、部屋と赤ちゃんが収まることを確認しています。
お世話4種は、ヘッドレスブラウザで「ボタン → 移動 → ドラッグ → ごほうび → ラグへ戻る」まで
通しで動くこと（ほしが1枚ずつ増え、欲求が 0 に戻ること）を確認済みです。
なお、描画速度はソフトウェアレンダラでの測定になるため、実機の fps は未計測です。

## セーブデータ

`localStorage` のキー `baby-care-game/v1` に、欲求4種・ほしの数・ミュート設定を保存します。
5秒ごと、お世話の完了時、アプリを閉じるときに書き込みます。壊れていた場合は初期値で開始します。
