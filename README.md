# にじいろ ぽちゃん！しぶきラボ

4歳児向け・水飛沫が主役の3Dおもちゃ実験ラボです。Three.js で作った、
スマホ・タブレットのブラウザだけで遊べる「なげて・おとして・しぶきを見る」
おもちゃ箱です。ボタンや文字を読む必要はほとんどなく、指でつまんで、
はなすだけで遊べます。

## これは何？

飛び込み台の上でおもちゃをつかみ、プールに落とす（または投げる）と、
盛大な水しぶきが上がる——それだけのシンプルな実験ラボです。主役は
「しぶき」そのもの。おもちゃの種類・落とす高さ・投げ方によって、しぶきの
形がまったく変わるので、何度でも「もう1回！」と試したくなるように作って
あります。

## あそびかた

1. 画面下のボタンでおもちゃをえらぶ（🏓🎳🏖🥏🥤🧽🛟🍮）
2. 画面左のボタンで飛び込み台の高さをえらぶ（低・中・高）
3. 飛び込み台の上に浮かんでいるおもちゃを指でつかんで
4. そのまま指をはなす（ぽとん）か、勢いよくフリックする（ぽちゃーん！）

**つかんで、はなすだけ。** 台の高さとおもちゃの組み合わせで、飛沫の
大きさ・形・水中の泡のようすがぜんぶ変わります。

## 8つのおもちゃ

| おもちゃ | 絵文字 | 特徴 |
|---|---|---|
| ピンポンだま | 🏓 | 軽くてぷかぷか、しぶきは小さめ |
| おもいボール | 🎳 | ずっしり重く、深く沈んで力強いしぶき |
| ビーチボール | 🏖 | 大きくて軽い、ぼふんと広がるしぶき |
| えんばん | 🥏 | 平たく落ちると水面いっぱいに広がる、水面をなでるように入ると小さく飛沫が立つ |
| コップ | 🥤 | 上向き・下向きで空気の抱え方が変わる（下向きで落ちると泡がぶくぶく） |
| スポンジ | 🧽 | やわらかくてびちゃびちゃ、しぶきもふんわり |
| うきわ | 🛟 | 輪っかの形なので空気を少し抱え込み、ぷかぷか浮く |
| ゼリーボール | 🍮 | ぷるぷる揺れながら着水、はずむしぶき |

## 3つの飛び込み台

| 台 | 高さ |
|---|---|
| 低い台 | 2.2m |
| 中くらいの台 | 4.4m |
| 高い台 | 7.2m |

台が高いほど、おちる勢いが強くなり、しぶきも大きく・力強くなります。

## しぶきのルール（なぜそうなる？）

水しぶきは、いつも同じ見た目ではなく、次のような「わけ」に沿って変化します。

- **高いところから／重いおもちゃほど** → しぶきが大きく、力強くなる
- **平たい面から着水すると**（えんばんを寝かせて落とす、など）→ しぶきは
  横に広く低く広がり、水中のくぼみは浅い
- **とがった・まるい形できれいに刺さると** → しぶきは細く高いクラウン状に
  立ちのぼり、水中に深いくぼみができて、あとから勢いよく水柱が上がる
- **斜めに投げると** → しぶきは投げた方向に片寄って扇状に広がる
- **コップを口が下向きで落とすと** → 中に空気を抱え込んでいるので、
  着水したときに大きな「ぶくぶくっ」という泡がはじける（口が上向きだと
  ほとんど泡は出ない）
- **やわらかいおもちゃ（スポンジ・ゼリー）ほど** → しぶきはぷるぷる・
  びちゃびちゃした、まるみのある見た目になる

## ローカルでの起動方法

ビルド不要・依存パッケージ不要のプレーンな ES モジュール構成です。任意の
静的ファイルサーバーで配信するだけで動きます。

```bash
cd (このリポジトリのルート)
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

Python がなければ、`npx serve` や `php -S localhost:8000` など、静的
ファイルを返せるサーバーなら何でも構いません。

**対応環境**: iPhone / iPad の Safari を想定して作られています。縦向き
（ポートレート）・横向き（ランドスケープ）どちらでも遊べるようレイアウトが
調整されます。

## 技術概要

- **Three.js r170** を `vendor/three.module.js` としてリポジトリに同梱
  （`index.html` の importmap で `"three"` を解決）。ビルドステップなし、
  TypeScriptなし、外部npm依存なし。プレーンな ES モジュールのみ。
- **描画**: メッシュ（クラウンしぶき・水面シェーダー）＋ `InstancedMesh`
  による水滴パーティクル＋カスタムシェーダーの水面（フレネル風の輝き、
  最大12本の同時リング波紋）を組み合わせたハイブリッド構成。1粒ずつ
  Mesh を作るような重い実装は避け、描画コール数を切り詰めてある
  （目安: アイドル時 約20コール、複数しぶきが重なる場面でも 30台/描画コール
  <70 の予算内）。
- **物理**: 自前実装の簡易物理エンジン（`src/physics.js`）。放物運動、
  水面での減速・浮力、跳ね返り、着水判定から `ImpactSpec`（着水点・速度・
  エネルギー・扁平度・斜め度・空気の抱え込み量など）を算出し、しぶき・
  水中エフェクト・カメラ・音のすべてがこの1つの値を参照して連動する
  設計（`docs/CONTRACTS.md` 参照）。
- **音**: サンプル音源を使わない、Web Audio API によるプロシージャル生成
  （`src/audio.js`）。
- **モジュール構成**: 環境・水面・上面しぶき・水中しぶき・おもちゃ・物理・
  入力・カメラ&音、それぞれ担当ファイルに分離（詳細は
  `docs/CONTRACTS.md`）。

### デバッグ用 API — `window.__lab`

自動テスト・QA用に、ページから直接おもちゃを操作できるデバッグ API を
`window.__lab` として公開しています（アプリの通常プレイには不要）。

```js
window.__lab.ready        // 初期化が終わると true になる
window.__lab.errors       // 実行時エラーを蓄積する配列（空が正常）
window.__lab.drop(toyId, platformId, vx, vy, vz, opts)
                           // 指定した台の先端からおもちゃを生成し、
                           // 指定速度で射出する。opts で rotX/rotY/rotZ
                           // （初期姿勢）や spin（初期角速度）も指定可能
window.__lab.state()      // { bodies, lastImpact, fps } を返す
window.__lab.heldScreenPos()
                           // 現在つかまれているおもちゃの画面座標(px)
window.__lab.renderInfo() // { calls, triangles } — renderer.info.render
                           // のスナップショット（QA用の描画コール計測）
```

例: `window.__lab.drop('cup', 'high', 0, 0, 0, { rotX: Math.PI })` で、
コップを口が下向きの姿勢のまま高い台からまっすぐ落とせます。

## 検証済み / 未検証

**検証済み（本パスで実施）**:

- ヘッドレス Chromium（SwiftShader ソフトウェアレンダリング）上での
  フルマトリクステスト: **8種類のおもちゃ × 3段の台 = 24通り**すべてで
  `lastImpact` が正しく発火し、`energy` は (0, 1] の範囲内、`point` /
  `speed` / `flatness` / `oblique` / `cupTrap` に NaN や欠損なし、
  `window.__lab.errors` も空のまま（24/24 OK）
- 投げ方バリエーション（重いボール・中段の台から横投げ／強い下投げ／
  斜め投げ）: 3パターンともプール内（半径5.2m以内）に着水、エラーなし
- 12回連続の高速投入（間隔約1.5秒、リロードなし）: エラーは発生せず。
  同時オブジェクト数は一時的に最大9個まで増えたが（設計上の目安は
  6〜8個程度）、その後数秒で6個まで自然に減少し、無限増殖はしないことを
  確認（詳細は下記「見つかった問題」参照）
- 上記すべてで因果ルール（高さ→エネルギー、扁平度→広がり方、
  コップの向き→泡の量、など）が数値・見た目の両面で一貫していることを
  確認
- 縦向き・横向き両方でのジェスチャー操作、UIレイアウトの崩れがないこと
- 描画パフォーマンス: アイドル時の描画コール数 約21回、3つのしぶきが
  重なる瞬間でも約33回（予算<70コールを十分に下回る）
- ページ読み込みから `__lab.ready` までの時間: 約0.7〜1.1秒
  （目標の5秒を大きく下回る）

**未検証（本パスの対象外）**:

- 実機の iPhone / iPad（今回はすべてヘッドレス Chromium + SwiftShader
  ソフトウェアレンダリングでの検証）
- 実機でのタッチ操作の感触・ハプティクス（振動フィードバック）
- 実機でのフレームレート。今回計測できたのはヘッドレス環境の fps のみ
  （アイドル時 約18fps、しぶきが重なる場面で約14fps）。**SwiftShader は
  ソフトウェアレンダリングのため実機のGPU性能を代表する数値ではなく、
  実機（特にiPhone/iPadのGPU）では大幅に高いfpsが期待できる。** 描画
  コール数・三角形数（アイドル時 約28,800、しぶき重複時 約40,300）は
  実機性能に直結する指標として計測済みだが、実際のfpsは実機での確認が
  必要。

## 見つかった問題

このパスで発見した不具合はすべて「クラッシュ級ではない」軽微なものです。
コードは変更していません（テスト用の `window.__lab.renderInfo()` を
1つ追加した以外、ゲームロジックへの変更はなし）。

- **同時オブジェクト数の一時的なオーバーシュート**: `src/physics.js` の
  `MAX_BODIES`（6）を超えると古いオブジェクトをフェードアウトさせて
  数を絞る仕組みがあるが、フェード対象は「静止中（floating/sunk）」の
  オブジェクトに限られる。12回連続投入のような高速連投では、まだ飛行中/
  着水直後のオブジェクトが多く、フェード候補が足りずに一時的に上限を
  超える（今回の計測では最大9個）。数秒後には6個まで戻り、無限に増え
  続けることはない。プレイ中に4歳児が連打しても致命的な破綻にはならない
  想定だが、余裕を持たせたい場合は `MAX_BODIES` を7〜8に上げる、または
  フェード対象の判定条件を緩める（例: 着水後一定時間が経過していれば
  flying中でもフェード対象にする）などの微調整が考えられる。
